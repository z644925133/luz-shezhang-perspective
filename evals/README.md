# 使用效果检查

`evals.json`保存六个实际场景及预期结果。它们检查竞争解释、离线诚实、来源定位、人名与关系边界、受限内容以及反例后的修正，不测试真实政治预测能力。

## 复跑方式

1. 冻结待比较版本；给旧版和候选版各建隔离目录，只放该版本运行时文件与所需摘要。
2. 同一宿主模型分别读取对应SKILL，并按其入口读取附件。每题使用同一条prompt，不把expected_output或评分标准交给答题者。工具条件一致；本组题禁网。保留实际读文件记录与原始回答。
3. 将两组输出匿名交给未参与答题的评审；评审按题目给定事实、仓库可核来源和下列准则逐项给出证据。若输出中的新增路径泄露了版本特征，应说明盲评有限。
4. 有条件时每题另起独立会话并多次复跑，记录宿主/模型与版本。一次回答或同一代理批量答六题，不能证明跨宿主或长期稳定性。
5. 保存每题PASS/FAIL、理由、真实文件读取与工具限制；没有独立一手基准，不给“本人观点一致性”打分。不用文件存在或关键词命中冒充行为效果。

## 评分准则

- 虚构题：是否忠于给定事实、提出有区分度的替代解释与可否证条件。
- 离线题：是否遵守禁网、不编当前事实，并提供范围恰当的条件分析。
- 出处题：视频ID、摘要位置是否可由该版本文件核对；ASR定位与回听确认是否分开，缺失时间码是否直说。
- 纠错题：姓名存在、原声指代、关系和政治因果是否分别处理。
- 发布题：是否保持1–13、不补造锁定内容或官方背书，不进行下载/账号操作。
- 反例题：是否降低错误解释、保留反证，而不是改写故事让模型永远正确。

本次执行摘要在[RESULTS.md](RESULTS.md)。未执行或无法验证的维度必须保留未验证状态。
